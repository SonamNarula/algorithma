## Daily Operating System

| Block | Time | What |
|---|---|---|
| Concept | 45 min | Learn the day's pattern; write its C++ template from scratch |
| Core problems | 4–5 hrs | 10–15 problems/day. Time caps: 🟢 ≤ 15 min, 🟡 ≤ 25 min, 🔴 ≤ 40 min, then read hints |
| Upsolve | 45 min | Unsolved problems: study solution, re-code without looking |
| Revision | 20 min | Yesterday's templates + 1 random ⭐ from an older week |
| Log | 10 min | Problem, pattern, time taken, mistake type |

**Rules:** (1) Brute force first, then optimize; say complexity before coding. (2) Fail a problem twice → Redo Bucket. (3) Day 7 of every week = Review + Weekly Test. (4) Short on time → do ⭐ first, then 🟢/🟡; 🔴 problems are stretch. (5) Light day (college/CRT)? Minimum = all ⭐ + 6 problems; carry the rest to the weekly review day.

> Each day = **one pattern**. Inside a day, problems are grouped by **sub-pattern** and ordered 🟢 → 🟡 → 🔴 (⭐ first within a level), so you build the pattern step by step.

## Month 1 — Pure Foundation Phase

### Week 1 — Arrays & Two-Pointer Techniques (+ Hashing, Kadane, Binary Search)

**Patterns:** Time & Space Complexity (deep) • Linear Scan & Linear Search • Hashing (frequency, set, value→index, complement, prefix + map) • Prefix Sum, Suffix & Difference Array • Kadane's Algorithm & Subarray Problems • Two pointer technique • Sliding window basics • Binary Search (intro)  
**Site target:** 28–30 problems (Easy 10, Medium 18–20, Hard 0–2 optional) | **Planned:** 90 (🟢 44 / 🟡 42 / 🔴 4)

**Array Decision Framework** (use before coding any array problem)

| What does the problem ask? | Technique | Practised on |
|---|---|---|
| Single-element property, min/max, count | Linear scan / accumulation | Day 1 |
| Fast repeated lookup or frequency | Hashing (flowchart below) | Day 2 |
| Contiguous range / subarray, fixed-size window | Fixed sliding window | Day 5 |
| Contiguous range, window can be kept valid by shrinking/expanding | Variable sliding window | Day 5 |
| Contiguous range, window cannot be maintained | Prefix sums, hashing, or another range technique | Days 2–3 |
| Pairs or triplets, array sorted (or can be sorted) | Two pointers | Day 6 |
| Pairs or triplets, cannot sort | Hashing, or sorting with index preservation | Day 2 |
| Range sum queries | Prefix sum | Day 3 |
| Repeated range updates | Difference array | Day 3 |
| Maximum subarray sum | Kadane's algorithm | Day 4 |
| Matrix / grid | 2D traversal or matrix pattern | Day 3 |
| Search in sorted data (value / boundary / answer) | Binary search | Day 6 |
| **Always, last step** | Prove correctness, analyze complexity and edge cases | Every day |

**Hashing Flowchart** (what information must be remembered?)

| Information to remember | Structure | Typical problem |
|---|---|---|
| Occurrence count | Frequency map | Unique Number of Occurrences |
| Whether a value appeared | Hash set | Contains Duplicate |
| Index of a previous value | Hash map: value → index | Two Sum, Contains Duplicate II |
| Required complement | Calculate target − current | Max Number of K-Sum Pairs |
| Subarray sum condition | Prefix sum + frequency map | Subarray Sum Equals K |
| **After choosing** | Check update vs query order → analyze complexity and edge cases | Every hashing problem |
